# 实机 Push-T 任务中的 Diffusion Policy 输入输出说明（2026-07-25）

> 兼容说明：本文档不使用 LaTeX 命令，公式全部采用纯文本、Unicode 符号和代码块表示，可在大多数 Markdown 查看器中正常显示。

---

## 1. 任务概述

实机 Push-T 任务中，机械臂通过末端圆柱形推杆推动桌面上的 T 形物体，使其移动并旋转到目标区域。

典型系统包含：

- 顶视 RGB 相机
- 机械臂和末端推杆
- T 形物体与目标区域
- Diffusion Policy 策略模型
- 机械臂底层控制器

任务通常简化为二维平面控制：

```text
控制变量：推杆在桌面平面内的 x、y 位置
固定变量：推杆高度 z、末端姿态 R
```

---

## 2. 系统层面的输入和输出

Diffusion Policy 在系统层面完成的映射是：

```text
最近若干步观测  →  未来一段动作序列
```

以常见配置为例：

```text
观测长度 To = 2
预测长度 Tp = 16
执行长度 Ta = 8
```

含义是：

- 输入最近 2 个时刻的观测
- 预测未来 16 个动作
- 实际执行前 8 个动作
- 执行后重新观测，再次预测

可以简化成：

```text
最近两帧图像
+ 最近两个推杆位置
→ 未来 16 个推杆目标位置
```

---

## 3. 输入一：相机图像

在控制时刻 `t`，模型输入最近两帧图像：

```text
I[t-1], I[t]
```

图像通常包含：

- T 形物体的位置和朝向
- 推杆的位置
- 目标区域的位置
- 推杆与物体的接触关系
- 物体当前的平移或旋转趋势

假设单帧图像尺寸为：

```text
I[t].shape = [3, 96, 96]
```

两帧图像组合后：

```text
image.shape = [2, 3, 96, 96]
```

加入 Batch 维度后：

```text
image.shape = [B, 2, 3, 96, 96]
```

其中：

- `B`：Batch Size
- `2`：两个观测时刻
- `3`：RGB 三通道
- `96 × 96`：图像分辨率

### 为什么使用两帧？

两张连续图像可以帮助模型判断：

- 推杆运动方向
- T 形物体是否正在运动
- 物体是在平移还是旋转
- 推杆是否已经接触物体
- 推杆是否发生打滑
- 上一个动作产生了什么效果

---

## 4. 输入二：机器人自身状态

模型还会输入最近两个时刻的推杆二维位置：

```text
p[t-1] = (x[t-1], y[t-1])
p[t]   = (x[t],   y[t])
```

组合后：

```text
agent_pos =
[
  [x[t-1], y[t-1]],
  [x[t],   y[t]]
]
```

其形状为：

```text
agent_pos.shape = [2, 2]
```

加入 Batch 维度后：

```text
agent_pos.shape = [B, 2, 2]
```

在实机中，推杆位置通常由机械臂正运动学获得：

```text
关节状态 q[t]
→ 正运动学
→ 末端位置 (x[t], y[t], z[t])
```

Push-T 一般只使用平面位置 `(x, y)`，推杆高度 `z` 和末端姿态通常保持固定。

---

## 5. 一次完整的观测输入

在控制时刻 `t`，完整观测可以表示为：

```text
O[t] = {
  I[t-1],
  I[t],
  p[t-1],
  p[t]
}
```

伪代码：

```python
obs = {
    "image": [
        image_t_minus_1,
        image_t
    ],  # shape: [2, 3, 96, 96]

    "agent_pos": [
        [x_t_minus_1, y_t_minus_1],
        [x_t, y_t]
    ]   # shape: [2, 2]
}
```

图像版本通常不会直接输入 T 形物体的真实坐标和角度。模型需要从 RGB 图像中自行判断物体、推杆和目标区域的位置关系。

---

## 6. 策略最终输出什么？

Diffusion Policy 最终输出一段未来动作序列：

```text
A[t] = [
  a[t],
  a[t+1],
  ...,
  a[t+15]
]
```

每个动作是一个二维推杆目标位置：

```text
a[i] = (x_target[i], y_target[i])
```

完整输出形状：

```text
A[t].shape = [16, 2]
```

加入 Batch 维度后：

```text
action_pred.shape = [B, 16, 2]
```

示例：

```text
[
  [0.42, 0.71],
  [0.43, 0.69],
  [0.44, 0.66],
  [0.46, 0.63],
  ...
  [0.58, 0.40]
]
```

这些数值表示推杆未来应该依次到达的二维目标位置。

```text
模型输出的是推杆轨迹，
不是 T 形物体的未来轨迹。
```

---

## 7. 动作的具体含义

标准 Push-T 中，每个动作通常表示推杆的绝对二维目标位置：

```text
a[t] = (x_target[t], y_target[t])
```

简化的 PD 控制关系可以写为：

```text
p_ddot = Kp × (a[t] - p) + Kv × (0 - p_dot)
```

其中：

- `a[t]`：目标位置
- `p`：当前位置
- `p_dot`：当前速度
- `Kp`：位置增益
- `Kv`：速度增益

自定义实机系统也可以采用其他动作定义，例如：

```text
相对位移：a[t] = (Δx[t], Δy[t])
平面速度：a[t] = (vx[t], vy[t])
位姿增量：a[t] = (Δx[t], Δy[t], Δz[t], Δr[t])
```

训练与部署必须采用完全相同的动作定义、单位、坐标系和归一化方式。

## 8. Diffusion 网络内部的输入和输出

从整个策略看：

```text
观测 O[t]  →  动作序列 A[t]
```

但 Diffusion Policy 并不是一次直接生成最终动作，而是从随机噪声开始，通过多次去噪得到动作序列。

### 8.1 初始化随机动作

```text
A_K[t] ~ Normal(0, I)
```

形状为：

```text
A_K[t].shape = [16, 2]
```

### 8.2 单次去噪网络的输入

第 `k` 个扩散步骤的输入包括：

```text
1. 当前带噪动作序列 A_k[t]
2. 当前扩散步骤 k
3. 当前观测条件 O[t]
```

可以写成：

```text
(A_k[t], k, O[t])  →  去噪网络
```

伪代码：

```python
noise_pred = model(
    noisy_action,       # [B, 16, 2]
    diffusion_step,     # [B]
    observation         # image + agent_pos
)
```

### 8.3 单次去噪网络的输出

最常见的输出是预测噪声：

```text
epsilon_pred = model(A_k[t], k, O[t])
```

其形状为：

```text
epsilon_pred.shape = [B, 16, 2]
```

采样器利用预测噪声更新动作序列：

```text
A_k[t]  →  A_(k-1)[t]
```

重复多次：

```text
A_K[t]
→ A_(K-1)[t]
→ A_(K-2)[t]
→ ...
→ A_0[t]
```

最终的 `A_0[t]` 就是可执行动作轨迹。

所以：

```text
单次去噪网络：
带噪动作序列 + 扩散步骤 + 观测条件
→ 预测噪声
```

而整个策略是：

```text
机器人观测
→ 未来动作序列
```

## 9. 模型输出如何变成实机运动？

假设最终动作序列为：

```text
A_0[t] =
[
  [x[t],    y[t]],
  [x[t+1],  y[t+1]],
  ...,
  [x[t+15], y[t+15]]
]
```

模型预测 16 个动作，但系统通常只执行前 8 个：

```text
A_exec[t] = [a[t], a[t+1], ..., a[t+7]]
```

对于每个二维目标点 `(x_target, y_target)`，补上固定高度和固定姿态：

```text
末端目标位姿 =
(x_target, y_target, z_push, R_fixed)
```

完整转换流程：

```text
Diffusion Policy 输出二维目标点 (x, y)
                  ↓
加入固定高度 z 和固定姿态 R
                  ↓
生成机械臂末端目标位姿
                  ↓
逆运动学或笛卡尔控制器
                  ↓
生成关节位置、速度或力矩指令
                  ↓
机械臂执行运动
```

Diffusion Policy 通常不直接输出电机电流、电压或底层伺服器指令，而是输出较高层的动作目标。

## 10. 完整实机运行流程

假设外层策略控制频率为 10 Hz。

第一次预测：

```text
输入：I[9], I[10], p[9], p[10]
预测：a[10], a[11], ..., a[25]
执行：a[10], a[11], ..., a[17]
```

第二次预测：

```text
输入：I[17], I[18], p[17], p[18]
预测：a[18], a[19], ..., a[33]
执行：前 8 个动作
```

完整闭环：

```text
采集最近两帧图像和两个推杆位置
                  ↓
Diffusion Policy 预测未来 16 步
                  ↓
执行前 8 步
                  ↓
重新采集观测
                  ↓
重新预测未来动作
                  ↓
循环执行，直到任务完成
```

这种方式称为滚动时域控制。

---

## 11. 输入输出总结表

| 层级 | 输入 | 输出 |
|---|---|---|
| 整个策略 | 最近两帧图像、最近两个推杆位置 | 未来 16 个推杆二维目标位置 |
| 单次 Diffusion 去噪 | 带噪动作序列、扩散步骤、观测条件 | 预测噪声 |
| 动作执行模块 | 推杆二维目标位置 | 机械臂末端目标位姿 |
| 底层机器人控制器 | 末端目标位姿 | 关节位置、速度或力矩指令 |

## 12. 核心输入输出

### 策略整体

```text
输入：
I[t-1], I[t],
(x[t-1], y[t-1]),
(x[t], y[t])

输出：
[
  (x_target[t],    y_target[t]),
  ...,
  (x_target[t+15], y_target[t+15])
]
```

### Diffusion 单次去噪

```text
输入：
A_k[t] + 扩散步骤 k + 观测 O[t]

输出：
预测噪声 epsilon_pred
```

### 实机执行转换

```text
二维目标点 (x, y)
→ 末端目标位姿 (x, y, z_fixed, R_fixed)
→ 机械臂底层控制器
```

---

## 13. 最重要的理解

- 相机图像告诉模型 T 形物体、推杆和目标区域在哪里
- `agent_pos` 告诉模型推杆自身的准确二维位置
- Diffusion Policy 输出推杆未来应该经过的一串二维位置
- 输出动作经过坐标转换后变成机械臂末端目标位姿
- 底层控制器负责把末端目标位姿转换为真实机械臂运动
- 模型预测的是推杆动作，不是 T 形物体的未来轨迹
- 系统通过“观测 → 预测 → 执行 → 再观测”形成闭环控制

一句话概括：

```text
图像与机器人状态
→ 推杆未来动作序列
→ 机械臂真实运动
```
